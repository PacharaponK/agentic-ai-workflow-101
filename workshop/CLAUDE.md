## Commands

```bash
# Start server (with seed data)
npm start

# Development with auto-reload
npm run dev

# Run all tests with coverage
npm test

# Run a single test file
npx jest tests/wallet.test.js

# Run tests matching a pattern
npx jest --testNamePattern="deposit"
```

The server runs on `http://localhost:3000`. Swagger UI is available at `http://localhost:3000/api-docs`.

## Architecture

This is a **Digital Wallet REST API** built with Express.js. All state is held in-memory — data is lost on restart.

### Data flow

```
HTTP Request
  → server.js        (route registration, middleware)
  → walletController.js  (request parsing, HTTP responses)
  → wallet.js        (business logic, state mutation)
```

### Key design decisions

**`wallet.js` — `Wallet` class**: Single source of truth for all balance and transaction state. Methods (`deposit`, `withdraw`, `transfer`) throw on invalid input; controllers catch and map to HTTP 400. `transfer` internally calls `withdraw`/`deposit` then patches the last transaction's `type` field to `transfer_out`/`transfer_in` — no atomic rollback exists.

**`walletController.js`**: Exports the `wallets` Map alongside handlers so test files can clear state between tests (`wallets.clear()`). The `findWallet` helper sends the 404 response and returns `null`; callers must `return` immediately after a null check.

**`server.js`**: Uses `require.main === module` guard so importing in tests does not start the HTTP listener or run seed. Seed runs only when `NODE_ENV !== 'production'`.

**`swagger.js`**: OpenAPI spec is generated by `swagger-jsdoc` scanning `@swagger` JSDoc comments in `walletController.js`. To add a new endpoint to the docs, add a JSDoc comment in that file.

### Test structure

Tests live in `tests/`. Fixtures in `tests/fixtures/wallets.js` provide:
- `RAW_DATA` — plain objects for request payloads and assertions
- `createFixtureWallet(key)` — creates a fresh `Wallet` with preset balance (each call is isolated)
- `Scenarios` — preset wallet pairs with transaction history (e.g. `Scenarios.aliceToBob()`)

Tests import `app` from `server.js` and use `supertest` for integration-style HTTP testing without starting a real server.
